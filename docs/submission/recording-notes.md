# Finish the Kavu demonstration recording

The supplied `output/kavu-demo-silent.mp4` is a real screen recording of the working application, followed by clearly labelled explanatory cards. It is designed to run **4 minutes 25 seconds**. It has no audio or synthetic presenter. Shivam and the actual human team must add narration and camera footage before it becomes the final submission video.

## The three finishing steps

1. Import the MP4 into a video editor. Record the prepared [verbatim narration](video-script.md) against it; follow the pauses in the shot list. The MP4 already contains the application clicks, typing and numerical results.
2. Add Shivam's real camera at the opening and the actual eligible teammates at the opening or closing. A small camera overlay can preserve the screen demonstration. Do not replace people with names, avatars or generated faces. Keep final runtime between three and five minutes.
3. Watch the completed export, upload it to an accessible host, and test the exact link while signed out. Add only that verified link to the submission. The silent source is an editing asset, not a completed compliant video.

`output/demo-cues.srt` is an **optional editing cue track**, with chapter/action notes. It is not a word-for-word transcript and should not be mistaken for finished accessibility captions. You can import it as a timing guide, hide it before export, then generate or correct captions from the final real narration. No cue text is burned into the MP4.

## Capture provenance and regeneration

The recorder is `scripts/record-demo.mjs`. It controls a new Playwright-owned browser against the real local Kavu application; it does not use anyone's personal browser or account. The recording uses the **browser-local static demo mode**, matching the public preview, and has no server-account or live-forecast claim. Actual job creation, completion and measurements use the production shared workspace reducer. The narrative cards are separate HTML generated by the recorder, visibly labelled as explanatory/hypothesis material; they do not simulate application screens.

To regenerate without changing the main development server:

```sh
VITE_DEMO_ONLY=true npx vite --host 127.0.0.1 --port 5174 --strictPort
```

In another terminal:

```sh
KAVU_RECORD_URL=http://127.0.0.1:5174 node scripts/record-demo.mjs
```

The recorder requires the already installed Playwright Chromium and `ffmpeg`; it does not install software. Avoid editing frontend files during the capture, because development hot reload can interrupt the timing. Capture takes about four and a half minutes, plus encoding. The source context records 1920×1080 video, and ffmpeg produces an H.264 MP4 at 24 fps with no audio track and a web-friendly index.

Intermediate HTML cards, screenshots, original browser video and a capture manifest are under `output/build/video/`. They are working files rather than additional submission claims. The finished MP4 and SRT are the handoff assets.
